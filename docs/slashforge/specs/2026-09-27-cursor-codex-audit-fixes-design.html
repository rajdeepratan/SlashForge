Design — Cursor and Codex audit fixes (PR #58)

Goal: Fix the five findings in docs/slashforge/investigations/investigation-2026-09-27-1705.html. SlashForge's commands should run on Cursor and Codex only when typed, and the guides those agents read should describe their own behaviour, not Claude Code's.

Problem

  • F1: the four command skills are model-invocable on Cursor and Codex, so the agent can start them unasked.
  • F2: the commands guide teaches Claude Code frontmatter to Cursor and Codex. It never mentions Codex's agents/openai.yaml.
  • F3: three Cursor guide passages say Graphify installs a PreToolUse hook. On Cursor it writes a rule.
  • F4: the vendor guides still use Claude branding and Claude Code tool names.
  • F5: the install message names Codex a line late, the Trust page misses some paths, and host detection trusts folders before the agent's own knowledge.

Approach

Make the installer mark the four command skills as run-only-when-typed, in each host's own format. Fence the guide passages that differ per host, and reword the prose that doesn't differ so it is host-neutral.

Rejected alternatives:

  • Install Cursor-native .cursor/commands files. Codex has no equivalent, and it splits the shared skill set.
  • Rely on the gates. An unasked-for run still spends 15–120k tokens before the first gate.
  • Fence every Claude-worded sentence per host. Too much churn; neutral wording reads correctly on all three hosts.

Testing

  • F1 (RED first): after installAgentsFiles:
    • The four command SKILL.md files carry disable-model-invocation: true and have agents/openai.yaml with allow_implicit_invocation: false.
    • None of the nine discipline skills has either.
    • plannedAgentsWrites includes the four yaml paths.
    • After uninstall, no yaml remains.
  • F2 (RED first): the Cursor and Codex renders of slashforge-commands.md contain none of allowed-tools, argument-hint, user-invocable or $ARGUMENTS. The Codex render names openai.yaml.
  • F3 (RED first): no Cursor guide render contains PreToolUse.
  • F4 (RED first): no Cursor or Codex render contains Claude Setup, Claude Development Workflow, Claude could or via Bash.
  • F5 (RED first): the preamble mentions the fallback, and the install summary names Codex.
  • Then: the full suite, the regenerated Claude snapshot diff reviewed line by line, and the docs build plus the four checks.

Out of scope

  • How Claude Code installs anything. It stays flat commands, and only its guide wording changes.
  • Proving in the real Codex app that an unknown SKILL.md key is tolerated. This is added to the user's manual check: $slashforge-code must still be listed.
  • Changes to the discipline skills' invocation.
