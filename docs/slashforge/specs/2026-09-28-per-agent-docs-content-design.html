Design — Per-agent docs content and layout fixes

Goal: Give the docs a way to show only the selected agent's content, rewrite the pages that currently compare all three agents side by side, and fix the layout bugs that comparison caused — so each reader sees only their own paths, commands and features, on desktop and phone alike.

Problem

Investigation investigation-2026-09-28-1330.html found one root cause under most of eight findings: the docs can only swap three things per agent — command names (data-cmd), code-block tabs, and one example rule file (data-example-path). Everything else is written as a side-by-side comparison of Claude Code, Cursor and Codex. That is why picking Claude Code still shows Cursor and Codex content (#4, ~80 passages across 14 pages), why the per-agent tables are wider than the text column on desktop (#6) and push phones sideways, and why the quick start assumes Claude Code (#7).

Four more issues are independent of that root cause and are fixed directly: the Trust page's td:first-child { white-space: nowrap } on 90-character path cells makes its table overflow into mostly white space (#2); the header's agent picker plus search, menu and theme buttons overflow at 390px so every docs page scrolls sideways on phones (#5); the Installation page repeats itself (#3); and the sidebar places "Plan mode and /init" ahead of the setup steps (#8).

Finding #1 — the "Plan mode and /init" page — is also factually wrong, and the report's own guess about it was wrong too. Verified against vendor docs: all three agents have a plan mode (Claude Code and Cursor via Shift+Tab; Codex via /plan or Shift+Tab, added in v0.93.0 behind an experimental collaboration_modes flag). A built-in /init exists on Claude Code (writes CLAUDE.md) and Codex (writes AGENTS.md) but not Cursor, which has no documented built-in /init. The page's current opening ("Claude Code and Cursor ship a plan mode; Claude Code and Codex ship /init") is therefore inaccurate.

Approach

Chosen: a block-level per-agent content directive, plus splitting the wide per-agent tables into one narrow table per agent, plus the four direct layout fixes, plus a structural build check. This is the shape agreed in brainstorming (blocks + split tables; a structural width proxy; shrink the phone picker).

The directive reuses the machinery already in the repo. remark-directive is already a dependency and already powers :::note and :::steps; the accent colour, command spellings and example paths already switch off a single data-target attribute on <html>. So the new mechanism is one small remark plugin that emits a data-agent block, and a few CSS rules keyed to the data-target that is already set before first paint. No new client behaviour is needed — visibility is pure CSS.

Alternatives rejected. (1) A general row-and-column marking mechanism that keeps the multi-agent tables and hides non-selected rows/columns — more markup, more CSS, more JS, and it preserves the very tables that overflow; splitting the tables removes the overflow at the root instead. (2) Real pixel-level width measurement with a headless browser (Playwright) — accurate to the report's wording, but the repo's entire test suite has zero dependencies and every docs check is node:fs + regex over built HTML; adding a browser breaks that convention for marginal gain over a structural proxy that catches the actual regression cause.

Design

The work is seven units, each with a clear boundary.

1. The directive — docs/src/plugins/remark-agent-only.mjs (new). A remark plugin, registered in astro.config.mjs after remarkDirective (which must parse the ::: syntax first). It transforms a container directive :::agent[claude] … ::: into <div class="agent-only" data-agent="claude">…</div>. The label accepts one or more comma-separated targets — :::agent[claude,codex] emits data-agent="claude codex" — because some facts are shared by two agents but not the third (for example, /init is Claude Code and Codex). Target names are validated against TARGETS from src/targets.mjs; an unknown name emits a build file.message, the same way remark-callouts reports an unknown callout.

2. Visibility — docs/src/styles/site.css and docs/src/layouts/Base.astro. CSS hides every .agent-only block, then shows the one whose data-agent contains the active data-target (three rules, one per target, matching the existing accent-colour block). Because a reader with JavaScript disabled never runs the pre-paint script that sets data-target, the design adds a static data-target="claude" to <html lang="en"> in Base.astro; the inline script in Head.astro overrides it before paint for everyone else. This keeps the built HTML correct on its own — the same no-JS guarantee the existing check-docs-targets check enforces for command spellings.

3. Page rewrites — the affected content under docs/src/content/docs/. Each page's cross-agent passages become per-agent blocks so a reader sees only their own; cross-agent facts stay in prose only where the comparison is the point (that one install covers all three, the CLI reference's Hosts section, Migrating, the changelog). The wide 5-column per-agent tables (#6) are replaced by one narrow table per agent inside :::agent blocks — which also removes the Trust overflow (#2) and fixes the quick start (#7). Pages, worst first per the report: reference/cli.md (22 mentions, two tables 758/728px), reference/troubleshooting.md (11), guides/installation.md (8, plus the #3 duplication), reference/migrating.md (10 — largely stays cross-agent by design), guides/introduction.md (6, tables 1046/812px), guides/plan-mode-and-init.md (the #1 rewrite, table 805px), commands/slashforge-setup.md (table 812px), and guides/trust.md (the "What it writes" table).

4. The "Plan mode and /init" rewrite (#1). Reworked to the verified matrix using the new directive: plan mode is described for all three agents; /init is shown for Claude Code and Codex only, with a Cursor block stating it has no built-in /init and pointing to /slashforge-setup. The frontmatter description is corrected. Uses :::agent[claude,codex] for the shared /init facts and single-target blocks for the differences.

5. The Trust first-cell fix (#2). Splitting the "What it writes" table into per-agent tables makes each first cell a single short path, so the overflow is largely gone. In addition, td:first-child { white-space: nowrap } in site.css is relaxed so a genuinely long path cell may wrap rather than force the column wide — scoped so ordinary short identifier cells still read on one line.

6. The phone header fix (#5) and sidebar order (#8). A CSS media query at phone widths collapses the header picker to its value only (dropping the "Agent:" label, the way .agentsw__label already drops at 640px and the brand wordmark drops at 374px), so brand + picker-value + search + menu + theme fit within 390px. And in src/nav.ts, "Plan mode and /init" moves to after "Installation" in the "Start here" group; FLAT and the pager follow automatically.

7. The width regression check — .github/scripts/check-docs-width.mjs (new). A static post-build check in the existing style (node:fs over dist/, no browser). It fails if any content table carries per-agent columns — a header row naming two or more of Claude Code / Cursor / Codex — since that is the exact shape that overflowed, and if a content table exceeds a column-count budget. It is wired into ci.yml alongside the other check-docs-* steps. The precise header-detection rule and column budget are pinned in the plan.

Testing

Unit (node --test, zero-dep, alongside the existing test/docs-targets.test.js): the new plugin renders :::agent[claude] to the expected data-agent markup, handles comma-separated multi-target labels, and rejects an unknown target name. Build check: check-docs-width.mjs passes on the rewritten dist/ and fails on a fixture table that carries agent columns; added to ci.yml. Regression: the existing checks (check-docs-targets, -a11y, -links, -facts, and the docs-claims / docs-targets unit tests) still pass, and astro build stays green. Manual: astro preview — switching the agent shows and hides the right blocks; with JavaScript disabled the page shows Claude Code content; the header fits at 390px with no sideways scroll; no content table overflows the text column at 1440px.

Out of scope

  • Real pixel-level width measurement (would add a headless-browser dependency, against the repo's zero-dep convention).
  • A per-row or per-column table-hiding mechanism — tables are split per agent instead.
  • Any change to the existing command-name, code-block-tab, or example-path switching, which already works.
  • The landing page and the redirects, which the investigation confirmed are already correct.
  • New product claims about Cursor/Codex features beyond correcting the verified plan-mode / /init facts.
