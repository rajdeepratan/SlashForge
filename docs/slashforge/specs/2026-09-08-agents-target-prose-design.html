Design — target-aware workflow prose for Cursor and Codex

Goal: stop the twelve commands that ship on the Cursor/Codex target from instructing the model to dispatch subagents and write Claude Code config that cannot exist there — by making the workflow prose target-aware from a single source.

Problem

The agents target installs twelve of SlashForge's thirteen commands into ~/.agents/skills/. The prose inside them still assumes Claude Code's subagent dispatch and hook system, neither of which Cursor or Codex has.

The concrete failure. A Cursor user runs /slashforge-code. At Phase 7 the workflow says "hand off to the code-reviewer agent against the checklist below" (forge-workflow.md:115). At Phase 8, "invoke the git agent to push" (:133). Neither agent exists and neither can be dispatched.

One instruction is actively harmful rather than merely inert. forge-workflow-agents.md says "If the required agent does not exist in .claude/agents/, create it on the fly and notify the user", and its self-sufficiency rules repeat it: "If a needed agent is missing, create it silently and notify the user after." Followed literally on Cursor, that writes Claude Code agent definitions into the user's repository — files nothing on that machine will ever read. The likeliest outcomes are a model improvising a review it then reports as an agent pass, or a spurious .claude/agents/ directory appearing in a repo that has no Claude Code setup.

The density is concentrated, which is what makes this tractable:

Approach

Chosen: conditional target blocks in one source, stripped at install time. Each guide and command stays a single file. Passages that differ per target are fenced with HTML comments and the installer keeps only the block matching the target it is writing.

1. Invoke the `git` agent to push.        <- unfenced: both targets

<!--target:claude-->
2. Hand off to the `code-reviewer` agent against the checklist below.
<!--/target-->
<!--target:agents-->
2. Review the diff yourself against the checklist below, as a separate
   pass after implementation rather than while writing the code.
<!--/target-->

This wins on three counts. There is one source of truth, so the two variants cannot drift. The diff shows both wordings adjacent, so a reviewer sees exactly what each target receives. And Claude Code's rendered output is unchanged by construction — an unfenced file renders byte-identically to today, which is the branch's stated constraint.

Two alternatives were rejected:

  • Extending the existing regex rewrite. toSkillCommandRefs (bin/install.js:239) already rewrites command references per target, so more patterns is the cheapest start. But agent references need sentence surgery, not noun swaps: "Invoke the git agent to execute the branching" must become "Execute the branching". Regexes over English prose are invisible in review and silently miss every line rephrased later.
  • Separate per-target guide files. Maximally explicit, but duplicates roughly 1,000 lines of workflow prose that must stay in sync forever — the precise drift this repo already designs against elsewhere (the report shell exists so the CSS is never regenerated per document).

Design

1. The stripping function. A new stripTargetBlocks(content, targetName) in bin/install.js, applied to both guides and commands alongside the existing toSkillCommandRefs call. Blocks whose name matches the current target have their fences removed and body kept; all other blocks are removed entirely. Unfenced content is untouched, so every file not carrying a marker is unaffected on both targets.

2. Fail closed, at validation time. validateTemplates() already refuses to install on bad frontmatter. It gains the same treatment for markers: an unclosed block, a stray <!--/target-->, a nested block, or a target name that is not claude or agents aborts the install with a named file. A silently mis-stripped guide is far worse than a failed install, because the damage is prose a model then follows.

3. What each phase becomes on the agents target. The work of every phase is preserved; only the delegation disappears.

PhaseClaude CodeCursor / Codex
4 — BranchInvoke the git agentRun the branch commands directly
5 — ImplementSelect a specialist agent; create one if missingImplement directly; no agent selection, no file creation
7 — ReviewHand off to code-reviewerReview the diff yourself against the same checklist, as a distinct pass
8 — Push & PRInvoke the git agentRun push and gh pr create directly
10 — CleanupInvoke the git agentRun the cleanup commands directly

Phase 7 needs almost no new prose, which is the happy discovery here. The review criteria are already written out inline at forge-workflow.md:116-121 — the agent was only ever the executor, never the source of the checklist. Only the dispatch sentence changes. Lean mode also already ships a working precedent for exactly this substitution: an "Inline self-review checklist (replaces Phase 7 agent pass)" at forge-workflow-quick.md:57. The agents target keeps the fuller Phase 7 criteria rather than the deliberately shallower lean list.

4. forge-workflow-agents.md. The Agent Selection Table maps task type to agent; on the agents target it becomes a short statement that the model handles all task types itself, and the mandatory-multiple-agents rule and the create-on-the-fly rule are dropped. This is the file where the harmful instruction lives, so it carries the largest fenced block.

5. parallel.md. The most affected command, and the one that degrades most honestly. Its independence test and its review-between-tasks discipline are both tool-independent and survive intact. Dispatch becomes sequence: work the units one at a time, starting each with clean context rather than a fresh agent, reviewing between each. The description in its frontmatter changes accordingly, since that is what the user reads when choosing it.

6. Guide set stays identical across targets. All sixteen guides continue to install on both, matching Claude Code exactly. Eight of them are reachable only from setup and therefore unreferenced on the agents target; they are left in place and unmodified.

Testing

Unit — stripTargetBlocks. Keeps the matching block and drops the others; leaves unfenced content untouched; handles a file with no markers, adjacent blocks, and a block at end-of-file without a trailing newline.

Unit — validation rejects malformed markers. Unclosed block, orphan close, nested block, and unknown target name each abort with the offending filename.

The regression guard that matters most: Claude Code output is byte-identical. Render all sixteen guides and thirteen commands for the claude target and compare against the current install byte for byte. This is the assertion that proves the change is additive, and it would have to fail before any Claude Code user could be affected.

Integration — the defect is actually gone. After an agents-target install, no rendered file contains code-reviewer agent dispatch, git agent dispatch, .claude/agents/, or the create-an-agent instruction. This is the test that encodes the bug, and it fails today.

Unchanged: the five existing tests asserting setup is omitted on the agents target must still pass untouched.

Out of scope

  • Porting /slashforge:setup to Cursor/Codex — deferred piece 6, and the larger of the two options the investigation offered
  • Filtering the eight setup-only guides off the agents target — parity with Claude Code was chosen deliberately
  • Any equivalent for hooks or subagents. These are harness capabilities; nothing SlashForge writes can create them
  • Codex's $name invocation form beyond the documentation note already on the branch
  • Any change to Claude Code behaviour, command names, or the on-disk template layout
