Design — Cursor and Codex targets

Goal: npx slashforge --target cursor installs the workflow commands and discipline skills into .agents/skills/, where Cursor and Codex both discover them — with Claude Code's install byte-identical to today.

Problem

SlashForge has claimed "Cursor and Codex targets are planned" since v3.0.0, across five user-facing surfaces including the npm package description. No implementation exists. A Cursor or Codex user who installs the package today gets a successful install that their agent cannot discover at all.

Investigation (docs/slashforge/investigations/investigation-2026-08-23-1553.html) found the port is now much cheaper than when the claim was written: both targets implement the Agent Skills standard (SKILL.md with name/description frontmatter), which is the shape SlashForge's files already have, and all vendor coupling flows from one function — resolveTarget() at bin/install.js:186.

Approach

Chosen: installer-side destination mapping. Templates stay flat .md files. installFiles() gains a second layout, mapping each template to a per-vendor destination and rewriting the frontmatter name as it renders. Claude Code's code path is untouched.

This works because {{INSTALL_PATH}} already carries guide cross-references at render time (renderTemplate(), bin/install.js:170). Pointing it at the agents guides directory keeps every reference between guides valid, so no template content changes.

Two alternatives were considered and rejected:

  • Restructure templates on disk to <name>/SKILL.md. Churns all 13 command and skill files, and forces Claude Code either onto .claude/skills/ — losing the /slashforge: namespace and breaking every existing user — or into maintaining two on-disk layouts for one set of content. Destination is a render-time concern, not a source-layout one.
  • Symlink .agents/skills/ at .claude/commands/. Cannot work: one layout is flat files, the other is directories containing SKILL.md. There is no symlink that bridges the two shapes.

Design

1. Target descriptor. resolveTarget() takes a target alongside the existing project flag, driven by a table:

const TARGETS = {
  claude: {
    root:           '.claude',
    commandsSubdir: 'commands',
    layout:         'commands',   // .claude/commands/slashforge/<name>.md
  },
  agents: {
    root:           '.agents',
    commandsSubdir: 'skills',
    layout:         'skills',     // .agents/skills/slashforge-<name>/SKILL.md
    namePrefix:     'slashforge-',
    omit:           ['setup'],
  },
};

It returns today's shape plus layout, namePrefix and omit. Guides land in <root>/setup/slashforge/ for both targets, so installPath resolution is unchanged in form.

2. Two layouts in installFiles(). The commands layout is today's behaviour, unchanged. The skills layout writes a directory per command:

TemplateClaude targetAgents target
slashforge/code.md.claude/commands/slashforge/code.md.agents/skills/slashforge-code/SKILL.md
slashforge/tdd.md.claude/commands/slashforge/tdd.md.agents/skills/slashforge-tdd/SKILL.md
slashforge/setup.md.claude/commands/slashforge/setup.mdomitted this cycle
forge-*.md, assets~/.claude/setup/slashforge/~/.agents/setup/slashforge/

3. Frontmatter rewrite. Templates declare name: /slashforge:code. Cursor requires name to be lowercase letters, digits and hyphens only, and to match the parent folder. The skills layout rewrites that single line to name: slashforge-code; description and body pass through untouched.

4. CLI surface. --target claude|cursor|codex|agents, defaulting to claude. cursor and codex are aliases for agents — users will type the vendor they use, and the alias layer means a future split into .cursor/skills/ needs no CLI break. --target composes with the existing --project, --dry-run and --yes, and is honoured by status and uninstall.

5. meta.json gains a target field so status and uninstall can report and clean the right install.

6. Claim updates. README.md:27, the npm description in package.json, docs/src/content/docs/guides/introduction.md:135 and docs/src/content/docs/reference/migrating.md change from "planned" to the shipped state, noting that Codex invokes with $name rather than /name and that setup is Claude Code only for now.

Risks & edge cases

  • Uninstall must not touch a user's other skills. .agents/skills/ is shared ground. Uninstall removes only slashforge-* directories and prunes skills/ only when empty — mirroring the existing namespace-dir care at bin/install.js's uninstallFiles().
  • Omitting setup must be visible, or Cursor users will read it as a broken install. The installer prints the omission and why.
  • Codex arrives untested. It reads .agents/skills/, so it should work, but this cycle validates against Cursor only. The claim wording reflects that.
  • Pre-existing: the Claude path depends on .claude/commands/<ns>/ subdirectory namespacing, which is absent from the current skills documentation. Not introduced here, but it is the mechanism the whole /slashforge: form rests on.

Testing

Node's built-in runner, extending test/install.test.js (777 lines).

  • Claude regression: every existing assertion runs unchanged and must stay green — this is the proof that current users are unaffected.
  • resolveTarget() across four combinations: claude/agents × global/project.
  • installFiles({target:'agents'}) writes .agents/skills/slashforge-code/SKILL.md, and writes no slashforge-setup directory.
  • Frontmatter contract: for every installed SKILL.md, the name matches ^[a-z0-9-]+$ and equals its parent directory name. This is the assertion that would have caught the raw /slashforge:code value.
  • Guide references resolve: a rendered agents-target command contains no literal {{INSTALL_PATH}} and points inside .agents/setup/slashforge.
  • Uninstall isolation: a foreign .agents/skills/someone-elses-skill/ survives uninstall --target cursor.
  • --dry-run --target cursor prints agents paths and creates nothing.
  • meta.json records the target.

Out of scope

  • Codex-specific artefacts — AGENTS.md, agents/openai.yaml, $name beyond a documentation note
  • The per-vendor rewrite of setup.md (deferred piece 6)
  • Degrading the subagent-dispatch, hooks and CLAUDE.md assumptions in the workflow prose — the forge-workflow-agents.md mandatory-agents rule and parallel.md still assume Claude Code
  • Writing .cursor/skills/ or .codex/skills/ directly
  • Any change to Claude Code behaviour, command names, or on-disk template layout
