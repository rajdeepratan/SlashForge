Design — Graphify per agent, docs audit and review fixes (PR #58)

Goal: Fix D1–D8 from investigation-2026-09-27-1745.html and the 3 Important and 5 Minor code-review findings on 21cb5d0..08e5560, so each agent is told how Graphify and SlashForge actually behave on it.

Problem

The guides and docs treat Graphify as if every agent worked like Claude Code.

  • On Codex, Graphify's hook is a deliberate no-op, and AGENTS.md carries the guidance.
  • The bare graphify install sets up Claude Code only.
  • Codex needs multi_agent = true in ~/.codex/config.toml.

The review also found:

  • a surviving "Claude cite";
  • Claude-only passages reworded against the earlier spec, two of them now ambiguous;
  • a contradictory Codex commands paragraph;
  • smaller wording and code-tidiness issues.

Docs gaps: slash-only troubleshooting, a Claude-era Migrating note, and missing notes on commands-only-when-typed and Codex's skill-list limit.

Approach

Per-agent <!--target:X--> blocks where agents really differ, and neutral wording elsewhere.

Graphify's second step becomes per-agent while keeping four commands on every agent:

  • Claude Code: graphify install.
  • Codex: graphify install --platform codex.
  • Cursor: graphify install --platform agents, which puts the skill in ~/.agents/skills/, where Cursor reads it.

Rejected alternatives:

  • Dropping step 2 on Cursor. Cursor loses the /graphify skill, or only gets it through Claude's folder, and the step counts diverge.
  • Reverting every Claude-only passage verbatim. "In the shell" and "the agent" are correct in Claude Code too.

Testing

Each of these is written first and seen to fail:

  • D2: the Codex graph render has graphify install --platform codex, Cursor's has --platform agents, and neither has a bare graphify install line.
  • D1: no Codex render says the hook "surfaces" or "handles" context.
  • D3: the Codex graph render names multi_agent = true.
  • R-I1: cite is in the banned regex.
  • R-I3: the Codex commands render doesn't say to front-load the description for a command.
  • R-M1: no Cursor or Codex render says "Skill tool".
  • R-M3: the Codex render says $run-checks.
  • R-M4: a custom commandFiles list keeps the frontmatter flag and the yaml in step.
  • R-M5: the helper throws on content with no closing fence.

Docs-only items (D4–D8) are checked by the docs build and its four checks.

The Claude snapshot is regenerated, and every changed line is reviewed against this table. Then the full suite runs on Node 24 and 18.

Out of scope

  • Verifying Graphify commands by running them in real apps. That is the user's manual check.
  • Changing Graphify's own behaviour, or pinning a Graphify version.
