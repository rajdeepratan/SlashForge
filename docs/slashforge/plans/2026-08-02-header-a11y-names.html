Plan — accessible names for the header social links

Goal: Give the four header social links an accessible name, and add a CI guard that fails the build if any interactive element loses one again.

Architecture

Two tasks, in a deliberate order. The guard is written and proven to fail against the current build first; only then are the labels added and the guard proven to pass. A check that has only ever passed is not evidence that it can fail.

The guard follows .github/scripts/check-docs-links.mjs in structure, style and conventions — an ESM script run from docs/ against the built dist/, emitting ::error file=…:: annotations and exiting non-zero on findings.

Tech stack

Node built-ins only — node:fs and node:path, ESM. No parser library and no test framework: the repo root has zero dependencies and its CI runs npm test with no install step.

Global constraints

  • Zero dependencies. No package may be added to run this check.
  • The guard treats title as insufficient. Stricter than the specification requires, and the entire point — accepting it passes the shipped bug.
  • Do not modify docs/package-lock.json. A macOS-regenerated lockfile omits Linux optional dependencies and breaks CI's npm ci.
  • Keep aria-hidden="true" on the SVGs and keep the existing title attributes — the artwork stays hidden, the tooltip stays working.
  • The existing suite (43 tests), the docs build, and the link check must all stay green.

  • ☑ Step 2: Write the guard 
    #!/usr/bin/env node
/**
 * Fails if any interactive element in the built docs has no accessible name.
 *
 * An icon-only <a> or <button> whose only child is an aria-hidden <svg> exposes
 * nothing to a screen reader. `title` deliberately does not count: it is the
 * last-resort fallback in the accessible-name computation, is announced
 * inconsistently, and never reaches keyboard or touch users at all. Accepting it
 * would mean passing on the exact bug this check exists to catch.
 *
 * Run from docs/ after `npm run build`.
 */
import { readFileSync, existsSync, readdirSync, statSync } from 'node:fs';
import { join, relative } from 'node:path';

const DIST = 'dist';

if (!existsSync(DIST)) {
  console.error(`::error::${DIST}/ not found — run the build first`);
  process.exit(1);
}

const pages = [];
(function walk(dir) {
  for (const entry of readdirSync(dir)) {
    const p = join(dir, entry);
    if (statSync(p).isDirectory()) walk(p);
    else if (p.endsWith('.html')) pages.push(p);
  }
})(DIST);

// Non-greedy match of a whole element. Nesting would confuse this, but an <a>
// inside an <a> is invalid HTML and the same holds for <button>, so the shape
// being checked cannot legally nest.
const ELEMENT = /<(a|button)\b([^>]*)>([\s\S]*?)<\/\1>/g;

let unnamed = 0;
for (const page of pages) {
  const filehtml = readFileSync(page, 'utf8');

  for (const [, tag, attrs, inner] of filehtml.matchAll(ELEMENT)) {
    if (!/<svg/i.test(inner)) continue;                 // not icon-only
    const text = inner.replace(/<[^>]*>/g, ' ').replace(/&[a-z#0-9]+;/gi, ' ').trim();
    if (text) continue;                                 // has visible text
    if (/\saria-label\s*=/i.test(attrs)) continue;      // named directly
    if (/\saria-labelledby\s*=/i.test(attrs)) continue; // named by reference
    if (/<title[\s>]/i.test(inner)) continue;           // named by the svg

    const href = (attrs.match(/href="([^"]*)"/) || [])[1];
    const hint = (attrs.match(/title="([^"]*)"/) || [])[1];
    console.error(
      `::error file=docs/${relative('.', page)}::<${tag}> has no accessible name` +
        `${href ? ` (href ${href})` : ''}` +
        `${hint ? ` — title="${hint}" does not count` : ''}`
    );
    unnamed++;
  }
}

console.log(`checked ${pages.length} pages`);

if (unnamed > 0) {
  console.error(`${unnamed} interactive element(s) with no accessible name`);
  process.exit(1);
}

console.log('every interactive element has an accessible name');

Verification of the whole change

The red-green evidence is the point, and it must be observed rather than assumed: the guard reports 4 before Task 2 and 0 after. If it was never seen failing, it is not known to work.

To re-prove it later, revert the labels, rebuild, run the guard, restore, rebuild, run again.

Out of scope

  • The other three categories in the audit report — only the missing-name rule is in scope.
  • Broader accessibility work: colour contrast, focus order, landmark structure.
  • The search, sections and theme controls, which are already named.
  • Whether these links should open new tabs at all — a product decision, not an accessibility fix.
