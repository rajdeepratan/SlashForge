Plan — SlashForge SDD Lifecycle

Goal: Give every SlashForge-managed repo a persistent Markdown spec home and a propose → apply → archive lifecycle folded into the existing phases, by adding one shared guide file and editing the phase templates — no new commands, no version bump.

Architecture

SlashForge ships template prose in templates/; bin/install.js renders each template per host (claude / cursor / codex), substituting {{INSTALL_PATH}} and stripping <!--target:--> blocks. The SDD convention is introduced as one new shared guide (slashforge-spec-home.md) that every phase references, so the layout and file formats live in a single place. The phase templates (workflow, brainstorm, plan, verify, request-review, setup) are then re-pointed at the new Markdown artefacts. The three top-level docs and the active//archive/ folders are created at runtime by the agent in the user's repo — they are not files the kit ships.

Tech stack

Node.js (no deps); node --test for tests; Markdown + HTML template prose. The Claude render is byte-pinned in test/fixtures/claude-render/ and regenerated by scripts/snapshot-claude-render.js.

Global constraints

  • Edit only templates/ — the copies under ~/.claude/setup/slashforge/ are generated; never edit them directly.
  • After ANY template edit, regenerate the pinned render with node scripts/snapshot-claude-render.js and review the diff; the render test is byte-exact.
  • Every template must keep valid frontmatter (name, description) and well-formed, own-line <!--target:--> markers, or validateTemplates refuses the install.
  • Living specs are Markdown under docs/slashforge/; investigation reports stay HTML; slashforge-splice.js and the report shell are untouched.
  • Feature-folder archive only — no reconciled per-capability specs.
  • The spec-home guide is host-neutral and renders for claude, cursor and codex alike (no omit entry).
  • No package.json version bump and no release.
  • Preserve all Graphify integration. setup.md and slashforge-workflow.md are dense with Graphify prose — the setup Graphify offer / provision / hook-in phases and the Phase-2 pre-plan graph-freshness consult. These tasks add to those files and must never remove or weaken any Graphify step; the render-fixture diff for each task must show only the SDD additions, never a deleted Graphify line.
  • npm test must pass at the end of every task.

Execution notes

Tasks are sequential — Tasks 3–6 all edit templates/slashforge-workflow.md and every task regenerates the shared render fixture, so they cannot run in parallel. Recommended approach: task-by-task with a review between each (not straight-through), since each task is an independently reviewable slice and the fixture diff is the main thing a reviewer checks.
