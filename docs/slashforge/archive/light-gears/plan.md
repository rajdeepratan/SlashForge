# Light Gears (`/slashforge-test` + `/slashforge-refactor`) — Plan

## Approach
Add two user-facing command templates following the kit's established command
shape (a thin `templates/slashforge/<name>.md` dispatcher that reads companion
guide files). `/slashforge-test` is a self-contained light flow driven by a new
`slashforge-workflow-test.md` guide; `/slashforge-refactor` inherits the base
ten-phase workflow with overrides in a new `slashforge-workflow-refactor.md` guide
(the same pattern `/slashforge-fix` uses). Wire both into `bin/install.js`, add
contract tests, regenerate the pinned render, and update the docs site and the
"six commands" claims.

## Tech stack
No new tech. Templates are Markdown with `<!--target:-->` blocks; installer is the
existing CommonJS `bin/install.js`; tests are `node:test`; docs are the Astro
workspace in `docs/`.

## Global constraints
- Zero runtime dependencies — Node built-ins only (`docs/slashforge/constitution.md`).
- Every guide/command `.md` ≤ 200 lines (≤ 500 for a `SKILL.md`); split, never truncate.
- Every `<!--target:x-->` has a matching `<!--/target-->`; valid names only: `claude`, `agents`, `cursor`, `codex`, `neutral`.
- After template changes, regenerate `test/fixtures/claude-render` with `node scripts/snapshot-claude-render.js`; never hand-edit a fixture.
- `/slashforge-test` never modifies production code and never opens a PR.
- No `package.json` **version** bump (description-only edit is allowed and does not publish).

## Files

**Create — templates (shipped product):**
- `templates/slashforge-workflow-test.md` (GUIDE_FILE) — the `/slashforge-test` flow: framework discovery → intended-behaviour derivation → spec-based test authoring → run → report; red path writes the full investigation contract. Referenced by both `test.md` and the refactor auto-run.
- `templates/slashforge/test.md` (COMMAND_FILE) — thin dispatcher for `/slashforge-test`: frontmatter `name: /slashforge-test`, Step 0 target resolution, reads the workflow-test + agents guides, announces, hands to the flow.
- `templates/slashforge-workflow-refactor.md` (GUIDE_FILE) — `/slashforge-refactor` phase mutations: baseline gate, zero-functional-change rule, auto-run trigger (references `slashforge-workflow-test.md`), before/after suite comparison, Phase 7 and Phase 8 overrides.
- `templates/slashforge/refactor.md` (COMMAND_FILE) — dispatcher for `/slashforge-refactor`: inherits `slashforge-workflow.md` + applies `slashforge-workflow-refactor.md`; `claude`/`agents` target blocks for Phase 7–10 dispatch; lists the four mandatory gates and the skill per phase (mirrors `fix.md`).

## Risks & edge cases
- **Pinned render churn.** Adding two commands + two guides changes the Claude render; the snapshot test fails until regenerated. Mitigation: Task 3 regenerates and reviews the diff; expect only additive changes.
- **Accidental publish.** Editing `package.json` is safe only because the version is unchanged — auto-release sees tag `v5.1.1` exists and skips. Never bump the version in this change.
- **GUIDE_FILES-registration test.** Creating a `slashforge-workflow-*.md` without registering it in `GUIDE_FILES` fails the suite by design — both guides must be added in the same task that creates them.
- **Composition on red.** When `/slashforge-refactor` auto-runs the test flow and a spec test fails, the run must halt with the bug report (and the written contract) rather than refactor on red — the guide must state this explicitly.
- **docs per-target markup.** New command pages must use the same `commandForm`/target markup as existing pages or `check-docs-targets.mjs` / `docs-targets.test.js` fail. Mitigation: copy an existing page as the template.
- **Line limits.** Each new guide risks exceeding 200 lines; keep the command dispatchers thin and push detail into the workflow guides, splitting if needed.

## Test strategy
- **Contract tests** (`spec-features.test.js`, the existing pattern): assert each command ships in `COMMAND_FILES`, installs to the right path, has `name: /slashforge-<x>` frontmatter, is rendered (no `{{INSTALL_PATH}}`), and that its instruction (command + companion guides, read via the `COMMAND_WORKFLOWS` map) carries the defining guarantees — e.g. `/slashforge-test` writes the full investigation contract on red and never edits production code; `/slashforge-refactor` enforces zero-functional-change and the before/after baseline gate.
- **Registration tests**: both guides present in `GUIDE_FILES` and on disk.
- **Pinned render**: regenerate and confirm `claude-render.test.js` passes with an intentional, additive diff.
- **Full suite**: `npm test` green.
- **Docs**: `npm run build` in `docs/` then `check-docs-links.mjs`, `check-docs-targets.mjs`, `check-docs-width.mjs`, `check-docs-a11y.mjs`, `check-docs-facts.mjs` all pass.
